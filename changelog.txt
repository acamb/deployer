0.1.1 2025/10/30:
    Commands that don't require a remote connection are now possible even if the remote is not available.
0.2.0 2025/10/31:
    Support for custom compose.yaml and version support
0.3.0 2025/11/01:
    Avoid keeping tar image in memory while loading from remote
0.3.1 2025/11/02:
    Fix issue with tar transfer
0.4.0 2025/11/29:
    Added "revisions" to allow multiple deployments (testing, zero-downtime deployments, etc)
0.4.1 2025/12/15:
    Version coherency check
    Better error reporting in build / load image
    --prune flag in deploy command to run docker prune -a -f on the server after the deploy
0.5.0 2025/12/31:
   - faster deploys for large images (the image tar is now compressed on the fly while deploying)
   - fixed some minor bugs in logs / start / deploy with revisions

    Breaking changes:
    Previously the containers name when using revisions was named "name_revision", which is not a valid domain name and some applications like tomcat will refuse to serve requests to that hostnames.
    The new naming schema is "name-revision", please re-deploy applications after this update to keep a consistent naming.
0.6.0 2026/03/21:
    Added 'push' command to send image/compose file without creating or restarting a container.
0.6.1 2026/05/22:
    Added 'Ports' command to list all ports currently in use by containers and their mapping to the host.
    Fixed deploy commands with images not built locally (previously remote images were not pulled)
    Added more test & coverage on server code
0.7.0 2026/07/25:
    Added EKVS integration to inject secrets into containers.
0.8.0 2026/08/XX:
    Added Continuity load balancer integration:
     - New server config: continuity_bin, continuity_advertise_base.
     - New client config: continuity_enable, continuity_config, continuity_pool,
            continuity_health_check_path, continuity_internal_port, continuity_remove_previous,
            continuity_advertise_base, continuity_private_key.
     - New 'lb-status' command to show the Continuity pool a project is published on.
    Added 'revisions_remove_previous' client config: after a successful --new-revision deploy,
    stop the revision(s) that were running before. If more than one is running you are prompted
    which to stop; if exactly one, it is stopped automatically.
